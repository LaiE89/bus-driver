# Bus Driver — Art Contract

> **Audience:** 3D artists, animators and sound designers delivering final assets.
> **Purpose:** if an asset meets this contract, it drops into the game with **no code changes and no scene edits**.
> **Status:** v1, 2026-09-29. Numbers marked *(provisional)* get re-checked after the first delivered asset.
>
> **Authority:** the technical contract lives in [`ROADMAP.md` Appendix A](ROADMAP.md#appendix-a--art--audio-interface-contract-authoritative), and **if the two disagree, Appendix A wins.** Until ticket T-M10-01 syncs this file, these known differences apply:
> - **Mimic flicker is done by the game.** No `_MimicFlicker` material parameter is needed.
> - **Dash screens** (clock, fare box, GPS) are `Anchor_Dash_*` empties that mark a flat screen area. Only the cabin mirror uses a UV quad.
> - **At least 12 passenger looks**, including 2 with hoods. A shared `React_TurnToCamera` clip and an `Anchor_HandR` are added.
> - **No Git LFS** (D41). Commit game-ready exports only. Keep source files (`.psd`, `.blend`, audio masters) in the shared drive. No file over 50 MB. Audio goes in as OGG.
> - **The art tools** (Make View, Validate Art, F2) arrive in milestone **M10**.
> - **Audio** uses one `SoundDefinition` asset per sound id (Appendix A.3), not Sound Controller entries.

## 1. How your art gets into the game

Every in-game object is made of two parts:

| Part | Owned by | Contains |
|---|---|---|
| **Logic root** | programmers | scripts, colliders, rigidbodies, gameplay anchor points |
| **`View` child** | **you** | meshes, materials, Animator, animation, visual-only effects |

The game currently runs with **greybox views**: capsules, cubes and spheres. Your asset replaces the greybox view of one object. Gameplay never looks at your meshes directly. It sends named signals, such as "sit down", "tell intensity 0.6" or "play death", which your Animator and materials respond to.

**What this means for you:**
- You never need to open or edit a level scene.
- You never add colliders, rigidbodies or scripts. Collision stays as designed, so hitboxes don't change when the art changes.
- Everything you deliver lives under `Assets/Art/`. Nothing in that folder is ever auto-generated or overwritten by our tools.
- **Tools ▸ Bus Driver ▸ Validate Art** tells you exactly what's wrong before anyone else sees it (§11).

## 2. Global rules

### 2.1 Units, axes, pivots
| Rule | Value |
|---|---|
| Units | **1 unit = 1 metre**. Export so that Unity imports at scale factor 1 (in Blender: Apply Scale, FBX "Apply Unit") |
| Up / forward | **+Y up, +Z forward** (the way the character or vehicle faces) |
| Transforms | frozen/applied. No negative scale on exported objects |
| Character pivot | on the ground, between the feet |
| Prop pivot | ground-centre of the footprint, unless the prop's section says otherwise |
| Bus pivot | matches the reference FBX (§5.1) |

### 2.2 Files and delivery
- **Meshes:** FBX (binary, FBX 2020 or newer). One asset per FBX, except modular kits (§6).
- **Textures:** PNG or TGA, power-of-two sizes. Keep the source files (PSD, SPP, blend) in `Assets/Art/_Source/` or your own repository, **never** loose in the asset folder.
- **Version control:** commit exported assets only (no source files; those go in the shared drive). No file over 50 MB. A pre-commit hook enforces this. There's no Git LFS.
- **One folder per asset:**
  ```
  Assets/Art/
    _Reference/          greybox reference FBXs (read-only, generated by us)
    _Source/             optional source files
    Characters/Passengers/<Name>/
    Characters/Monsters/<Name>/
    Vehicles/Bus/
    Environment/<Category>/<Name>/
    UI/  VFX/  Audio/
  ```

### 2.3 Naming
| Prefix | Type | Example |
|---|---|---|
| `SK_` | skinned mesh | `SK_Starer.fbx` |
| `SM_` | static mesh | `SM_Blocker_FallenTree_A.fbx` |
| `M_` | material | `M_Starer_Skin` |
| `T_` | texture + suffix | `T_Starer_Skin_BaseColor`, `_Normal`, `_MaskMap`, `_Emission` |
| `A_` | animation clip | `A_Passenger_Walk`, `A_Starer_Tell_HeadTrack` |
| `AO_` | animator override controller | `AO_Starer` |
| `Anchor_` | empty transform the game reads | `Anchor_Face` |

Texture suffixes drive the import settings automatically: `_BaseColor`, `_Normal`, `_MaskMap`, `_Emission`, `_Opacity`. Use them exactly.

### 2.4 Materials and the night look
- Shaders: **URP Lit** (default) or **URP Simple Lit** for distant or background props. Don't use custom shaders without first asking engineering, because scares, flicker and hallucinations drive material properties.
- Mask map: **R = metallic, G = ambient occlusion, A = smoothness** (URP convention).
- **Albedo range:** the game is mostly lit by headlights, a few lamps and dim cabin lights. Keep the base colour between **sRGB 30 and 220**. Pure black disappears, and pure white blooms under headlights.
- **Emissive surfaces** (lamps, dash screens, signs, reflectors) use an `_Emission` texture. The game controls the intensity at runtime so it can flicker lights, so **author emission at intensity 1**.
- **No baked lighting assumptions:** lights are dynamic and the bus moves. Don't bake light into albedo. Baked AO in the mask map is fine.

### 2.5 Budgets *(provisional; PC target)*
| Category | Triangles (LOD0) | Textures |
|---|---|---|
| Normal passenger | 8k–15k | 1 × 2K material set (a shared atlas is fine) |
| Monster (disguised + revealed) | 15k–25k | up to 2 × 2K |
| Monster **scare head** (close-up) | up to 15k extra | 2K |
| Bus: exterior + interior | 60k–90k total | up to 4 × 2K |
| Large prop (blocker, shelter, tunnel piece) | 2k–8k | 1K–2K |
| Small prop (sign, post, lamp, guardrail segment) | 200–2k | 512–1K (atlas welcome) |
| Tree | 1k–5k with LOD1/LOD2 + a billboard | shared atlas |

LODs: provide `_LOD0/_LOD1/_LOD2` meshes for trees and large props. They're optional for characters (the cabin is small and close).

## 3. Characters: normal passengers

### 3.1 Rig
- A **Humanoid-compatible** skeleton: standard biped with hips, spine, chest, neck, head, arms, hands and legs. Unity maps it to its Humanoid avatar, so **one animation set drives every passenger**.
- **Height:** 1.55–1.90 m. The greybox passenger is **1.75 m**, with the head centre at about 1.62 m.
- Bind pose: **T-pose or A-pose**, facing +Z.
- Finger bones are optional.

### 3.2 Required anchors (empty child transforms in the FBX)
| Anchor | Parent | Where | Used for |
|---|---|---|---|
| `Anchor_Face` | head bone | 10 cm in front of the face, +Z facing out | scare camera framing, stare direction |
| `Anchor_SeatContact` | hips bone | the underside of the pelvis | seating alignment (§3.4) |

### 3.3 Required animations (shared set, `A_Passenger_*`)
| Clip | Loop | Notes |
|---|---|---|
| `Idle_Stand` | ✓ | subtle; must read on low-res CCTV |
| `Walk` | ✓ | about **1.3 m/s** in place (no root motion); the game moves the character |
| `Sit_Down` | – | about 0.4 s; ends exactly in `Idle_Seated` |
| `Idle_Seated` | ✓ | subtle breathing and shifting weight |
| `Stand_Up` | – | about 0.4 s |
| `React_Flinch` | – | when the bus jolts or a scare happens nearby |
| `React_LookAround` | – | when a monster does something nearby |
| `Death` | – | when a monster takes the passenger (the Mimic); ends lying still |

**No root motion.** The game drives position and rotation.

### 3.4 Seating
The seat surface in the bus is at the height shown in the reference FBX. The game places `Anchor_SeatContact` on the seat anchor, so `Idle_Seated` must put the pelvis where a real seat would be. Test it in the reference bus.

### 3.5 Variety and the Mimic
- The Mimic **copies other passengers exactly**, so every passenger look must be a **self-contained prefab** (no shared scene objects).
- **Target: at least 8 distinct passenger looks.** Build them from a **modular kit** (bodies × heads × outfits × colour variants) and don't make them as one-offs.
- **Decoy looks** are normal passengers with odd traits: hood always up, sunglasses at night, facing backwards, an overcoat hiding the body. Build them as kit variants, not separate characters.
- Every look must be **identifiable on a grainy, greyscale CCTV feed** (it's heavily graded). Rely on silhouette and value contrast, not on colour.

## 4. Characters: monsters

Each monster uses the passenger rig and shared animations, **plus**:

1. **A disguised state** that looks like a (slightly off) normal passenger at tell intensity 0.
2. **Tell layers** that the game drives from 0 to 1 as the monster escalates. Build them as **blendshapes** or **material parameters** with the exact names below, or as clips on an additive animator layer. Say which you've used in the asset's README.
3. **A scare head:** a close-up quality head (or head variant) for kill scares. It's shown full-screen for about 1 s, so it gets its own budget (§2.5).
4. **Scare poses/clips** used by the scare Timelines.

### 4.1 The Starer
| Item | Name | Description |
|---|---|---|
| Tell | `Tell_HeadTrack` | **procedural**: the game rotates the head bone toward the active camera. Keep the neck deformation clean for ±70° yaw and ±30° pitch |
| Tell | `Tell_Stillness` | 0 → 1 fades out all idle motion (an animator layer weight) |
| Tell (blendshape) | `BS_EyesWide` | the eyes widen, lids retract |
| Clip | `A_Starer_LeanIn` | leaning over the driver's shoulder into the camera (kill scare) |
| Clip | `A_Starer_LensStare` | a face close to a CCTV lens (monster scare) |

### 4.2 The Whisperer
| Item | Name | Description |
|---|---|---|
| Tell (clip, additive) | `A_Whisperer_Tell_Lean` | leans toward a neighbour, looped |
| Tell (blendshape) | `BS_MouthWhisper` | a mouth-movement loop driven 0–1 |
| Tell (blendshape) | `BS_JawStretch` | high intensity only: the jaw is unnaturally long |
| Clip | `A_Whisperer_HandsOverEyes` | hands cover the driver camera from behind (kill scare); the hands need to look good close-up |

### 4.3 The Mimic
| Item | Name | Description |
|---|---|---|
| Disguise | — | **no fixed look**: it wears the look of the passenger it copies (the game instances that passenger's view) |
| Revealed look | `SK_Mimic_True` | its true form for the kill scare |
| Tell (material) | `_MimicFlicker` (float 0–1) | a shader hook on a **shared material function** that we provide. It makes any passenger look flicker or double. Artists don't need to do anything per passenger |
| Tell (visual) | no shadow | handled by the game (shadow casting is toggled) |
| Clip | `A_Mimic_TurnAll` | a snapping head turn toward the camera (the game plays it on every passenger at once) |
| Clip | `A_Mimic_WindowAppear` | appearing at the driver's window (kill scare) |

## 5. The bus

### 5.1 Dimensions (must match `Assets/Art/_Reference/REF_Bus.fbx`)
| Item | Value |
|---|---|
| Body | **12.0 m long × 2.55 m wide × 3.0 m tall**; the underside is at 0.45 m |
| Wheels | radius **0.50 m**; front axle at **z = +3.3**, rear axle at **z = −2.7** |
| Driver | on the **left** (x ≈ −0.7), at the front |
| Passenger door | **right side**, front, opening from **z = 4.1 to 5.5** (1.4 m) |
| Seating | **9 rows × 4 seats** (2 + aisle + 2), from z ≈ −5.2 to +2.8 |

The hull collider and WheelColliders are **fixed by physics tuning**, so the body must visually fit the collider box of the reference.

### 5.2 Separate meshes (children of the bus FBX)
- `Body_Exterior`, `Body_Interior` (the interior may be a separate FBX)
- `Door_Panel` (or `Door_Panel_A`/`_B` for bi-fold; tell us which). The game animates it.
- `Wheel_FL`, `Wheel_FR`, `Wheel_RL`, `Wheel_RR`. Each pivot is at the **wheel centre**, rolling around X.
- `SteeringWheel` (pivot at the column, rotates around its own axis)
- `Dash_GPS_Screen`, `Dash_Clock_Screen`, `FareBox_Display`: flat quads that get **runtime render textures**. Make them a UV 0–1 rectangle and give them a separate material.
- `Mirror_Cabin`: a flat quad for the Rear-view mirror item (render texture).
- `Light_Cabin_*` emissive fixtures (one mesh per light group, so we can flicker them independently).

### 5.3 Required anchors
| Anchor | Purpose |
|---|---|
| `Anchor_DriverHead` | first-person camera position |
| `Anchor_CCTV_Front`, `_Mid`, `_Rear` | CCTV camera mounts (the game places cameras here) |
| `Anchor_Seat_R{row}_{L2,L1,R1,R2}` | 36 seat anchors (e.g. `Anchor_Seat_R3_L1`), on the seat surface, +Z facing the way a seated passenger faces |
| `Anchor_DoorStep`, `Anchor_AisleAtDoor` | the boarding walk path |
| `Anchor_Headlight_L`, `_R` | headlight spot lights |

Anchors already exist in the greybox bus. Start from the reference FBX, keep its anchor transforms, and model around them.

## 6. Environment

The road surface itself is **generated from a spline**, so you provide **materials** for it, not meshes. Everything beside the road is modular props, placed by our tools.

### 6.1 Road and roadside
| Asset | Deliver |
|---|---|
| Road surface | a tiling material (asphalt, worn edge variant) plus line/marking decals |
| Shoulder / gravel edge | a tiling material |
| Guardrail | **modular 4 m segment** + end caps + a post, pivot at the start of the segment |
| Rumble strip / chevrons | a decal + a chevron sign |
| Reflector post | a small prop with an emissive reflector |

### 6.2 Blockers: dead-end side roads (D11)
Each blocker sits across an 8 m wide stub road. The pivot is at the road centre, and +Z faces back toward the main road.
`SM_Blocker_FallenTree`, `SM_Blocker_Fence_RoadClosed`, `SM_Blocker_ConcreteBarriers`, `SM_Blocker_CollapsedBridge`, `SM_Blocker_Gate`. At least **2 variants each** (`_A`, `_B`).

### 6.3 Stops (6 kinds)
Farm gate, gas station, campground, church, clinic, trailhead. Each needs a **stop sign/pole**, a **lamp** (emissive + the light position `Anchor_Light`), and an optional shelter. The **boarding zone is fixed by gameplay**: keep the kerb side within 1.8–4.4 m of the road edge clear for about 12 m.

### 6.4 Set pieces
- **Tunnel:** modular straight + curve + portal pieces, with emissive light fixtures on separate meshes (they flicker).
- **The cliff ("Dead Man's Bend"):** the cliff face and edge dressing with **no guardrail**, plus a visible long drop (it's seen in the third-person fall cam). Warning signs: `NO GUARDRAIL`, `SHARP CURVE`.
- **The bridge:** modular deck + railings.

### 6.5 Nature
Trees (conifers first): at least 4 species/variants, with LODs + billboards. Rocks and cliff chunks. Ground cover: a few cheap cards.

### 6.6 Collision for environment props
Don't add Unity colliders. If a prop needs a collision shape different from its bounding box, include simplified convex meshes named **`UCX_<MeshName>_NN`**. The import tool moves them to the logic root as colliders.

## 7. UI, VFX and textures for scares
- **Dash screens (GPS, clock, fare box):** a font plus a colour palette. The screens themselves are drawn by the game.
- **Scare overlays:** full-screen images/sequences (a face flash, static), 1920×1080, `T_Scare_*`.
- **CCTV:** a scanline/noise texture set (optional; a greybox version exists).
- **VFX:** a flicker/spark sheet and a breath fog. Coordinate with engineering on which system (particles vs. shader).

### 7.1 UI theme and fonts
- Every UI text in the game (menu, HUD, dash screens, shop, summary) uses a **role** from a single **`UITheme`** asset: `Title`, `Button`, `Body`, `HUD`, `Screen` (dash/CCTV displays).
- To deliver the final style, provide **font files (TTF/OTF, with licence)** plus a **palette** (text, highlight, disabled, danger, dash-screen glow) and sizes per role. Engineering generates the TMP font assets and fills in `UITheme`, and every screen updates at once. There's no per-screen restyling.
- The fonts need Latin Extended coverage and the digits/symbols `0–9 : $ + − . %`. The dash `Screen` font should read as a segmented or LCD display.
- The **main menu** has no painted background. It's a live shot of a bus stop built from the game's own art (GAME_SPEC §10b), so it updates automatically as stop, lamp, tree, bus and passenger art arrives. A **logo** image slot (PNG with transparency, at least 1024 px wide) replaces the placeholder title.

## 8. Audio (sound designers)
- Sounds are **named entries** on the Sound Controller. **Replace the clip on an existing entry; don't rename it.** New sounds: ask for a name, and it'll be listed in `SoundIds`.
- Format: WAV, 48 kHz, 16- or 24-bit. Mono for 3D-positioned sounds, stereo for music and UI.
- Naming: `amb_*` (ambience), `sfx_*`, `mus_*`, `vo_*`, with `_lp_` for loops and `_nl_` for non-loops (existing convention).
- **Loudness:** normalise so similar categories sit at similar perceived volume. Bake a fade into the tail of one-shots; don't rely on the game to fade.
- **Needed for greybox → final:** engine loop set, door open/close, footsteps (metal bus floor, gravel), CCTV switch/static, whispers (a stereo set that can pan hard), a sting set per monster, heartbeat, wind, forest night ambience, tunnel reverb tail, a cliff fall wind rush + impact.

## 9. Scares (Timelines)
Kill scares and monster scares are **Unity Timeline** assets under `Assets/Art/Scares/`. They bind to view anchors (`Anchor_Face`, the head bone) and the monster's scare clips. Artists or animators can retime and re-block them freely. Engineering only needs the **track names** unchanged: `Camera`, `Monster`, `Audio`, `Overlay`, `Lights`.

## 10. Delivery checklist (per asset)
- [ ] Correct folder and names (§2.2, §2.3)
- [ ] Scale 1, +Y up, +Z forward, transforms applied, correct pivot
- [ ] Required anchors present with exact names
- [ ] Required clips / tell blendshapes / material params present with exact names
- [ ] No colliders, rigidbodies or scripts (only `UCX_` meshes, if needed)
- [ ] Within the budgets (§2.5); LODs for trees and large props
- [ ] Textures use the suffix convention; the albedo range is respected
- [ ] Readable on the greyscale CCTV feed (characters)
- [ ] `README.md` in the asset folder: what's included, blendshape vs. layer choices, known issues
- [ ] **Validate Art passes** (§11)

## 11. Checking your work
1. Drop the files in the asset's folder. The import settings are applied automatically.
2. **Tools ▸ Bus Driver ▸ Make View from FBX** creates your view prefab with the right components and Animator setup.
3. **Tools ▸ Bus Driver ▸ Validate Art** lists every problem, with the reason (missing anchor, wrong pivot, over budget…).
4. Press Play in the Night scene and press **F2** to toggle between greybox and art, so you can compare size, pose and readability directly. The debug overlay (**F1**) has cheats to spawn any passenger or monster and to trigger its tells and scares.

> These tools are delivered in milestone **M8**. Until they exist, deliver to the folders above and engineering will integrate your asset manually against this contract.

## 12. Open questions for the art team
- The bus style: a modern low-floor city bus, or an older rural coach? This affects the interior layout (the seat count is fixed at 36).
- Bi-fold vs. single sliding door.
- Tell implementation per monster: blendshape vs. additive layer (either works; tell us).
- A shared passenger atlas vs. per-character texture sets.
- The main menu shot: which stop kind (trailhead or farm gate suggested) and the camera composition. The menu will show whatever art exists for those prefabs.
